## 〇、立项背景

之前主管认为"多账本约等于标签"建议不做，竞品调研后修正认知：

- 自部署开源圈（ezBookkeeping / Firefly III / Actual Budget）**集体没做**多账本
- 中文圈商业 App（钱迹 / 随手记 / 鲨鱼记账）**普遍做**多账本，是用户实际刚需
- 用户场景：旅行 / 装修 / 婚礼 / 出差报销等"**有时间边界 + 事项边界**的独立预算 + 独立统计"

经讨论确认：**v2.8.0 引入多账本**，以钱迹模式为参考起点（账户共享、其他隔离）。

---

## 一、功能本质

**账本 = 一个独立的"事项工作区"**，让用户能把**有时间/事项边界的开支**和**日常开支**彻底隔离统计与预算，但**钱包还是同一个钱包**。

### 与"标签"的差异

| 想做的事 | 标签方案 | 真·多账本 |
|---|---|---|
| 把一笔流水标记为"旅行" | ✅ | ✅（自动归属） |
| 看"旅行总额" | ✅ 标签筛选 | ✅ 切换账本即看 |
| **旅行独立的分类**（"门票/酒店/伴手礼"，跟日常"餐饮/交通"分开） | ❌ | ✅ |
| **旅行独立的统计** | 🟡 凑合 | ✅ |
| **总资产合并** | ✅ | ✅（账户共享） |

→ 真正用得上多账本的人要的是 **"事项级独立分类 + 独立统计"**，标签做不到。

## 二、隔离边界（**待用户拍板**）

参考钱迹模式 + 结合 EasyAccounts 现有功能，主管初步提议如下表，用户**Q1 需要逐项拍板**。

| 维度 | 钱迹做法 | 主管建议 | 用户决策 |
|---|:-:|:-:|:-:|
| 流水（账单） | 🔒 隔离 | 🔒 必须隔离 | ⏳ |
| 一级 / 二级分类 | 🔒 隔离 | 🔒 隔离（否则旅行账本里出现"日常餐饮"分类会混乱） | ⏳ |
| **标签 (Tag)** | — | 🔒 隔离 | ⏳ |
| **快记模板** | — | 🔒 隔离（旅行账本有"门票"快记，日常账本里没必要） | ⏳ |
| **定时记账规则** | — | 🔒 隔离（"房贷"归日常、"婚礼分期"归婚礼账本；规则归属哪个账本就生成到哪个账本） | ⏳ |
| **通知中心 / 事前提醒** | — | 🌐 共享列表，每条标注属于哪个账本（避免切账本看不到提醒） | ⏳ |
| **收支动作 (action)** | — | 🌐 共享（系统级概念，所有账本通用） | ⏳ |
| **账户 / 资产** | 🌐 共享 | 🌐 共享（钱包是同一个） | ⏳ |
| **统计页** | 🔒 跟随当前账本 | 🔒 跟随当前账本 | ⏳ |

## 三、现有用户的迁移（**待用户拍板**）

升级到 v2.8.0 时，所有现有用户都是单账本数据。处理方案：

| 选项 | 用户体验 |
|---|---|
| **(a)** 自动归属一个名为"默认账本"的容器，用户后续可改名 / 新建别的 | 中等打扰，明确告诉用户"现在有了多账本概念" |
| **(b)** 升级时强制让用户给当前账本起名才能继续用 | 强打扰 |
| **(c) ★主管建议** | **零感知**：单账本时 UI 完全不暴露账本概念；用户主动建第二个账本时再出现切换器、账本管理入口 |

主管倾向 **(c)**，理由：v2.7.0 升级影响已经够多（WebHook 内吸 + 配置 UI 化），多账本对存量用户应当无感。

---

## 四、账本模板（**待用户拍板**）

钱迹有"旅行 / 装修 / 婚礼"模板，自动生成对应分类。

| 选项 | 备注 |
|---|---|
| **(a)** 做厂家模板（旅行 / 装修 / 婚礼 / 出差报销 / 自定义） | 工作量中，提升开箱即用感 |
| **(b)** 不做，所有账本从空开始（用户自己加分类） | 简单，但用户首次创建账本 UX 不太好 |
| **(c) 折中** | **只做"复制现有账本"**：从已有账本（包括默认账本）拷贝其分类结构作为新账本起点，**不做厂家固定模板** |

## 五、各端交付目标（草稿，待 Q1-Q3 拍板后细化）

### 🟦 Server

1. 数据模型支持账本概念，所有按 §二决策的"隔离"维度数据带账本归属
2. 账本 CRUD（创建 / 改名 / 隐藏 / 恢复 / 删除）
3. 切换当前活跃账本（用户级状态）
4. 资源归属保护：账本被删时，关联流水按删除规则处理（钱迹是连账单一起删 —— 待用户决策）
5. 升级时数据迁移：所有存量数据归属默认账本

### 🟩 Web

1. **零感知**模式：单账本时不显示账本相关 UI（按 Q2 决策）
2. 账本切换器：参考钱迹，可放在主页顶栏或左上角
3. 账本管理页：列表 / 创建 / 改名 / 隐藏 / 恢复 / 删除
4. 创建账本时按 §四 决策提供"复制现有账本"或"模板"入口
5. 流水编辑器、统计页等所有账本相关页面，行为跟随"当前活跃账本"

### 🟨 AI

是否需要"按账本操作"（如"把这笔记到旅行账本"）—— **待用户拍板是否做 AI 端**

| # | 问题 |
|---|---|

| **Q2** | 现有用户迁移策略 §三：主管建议 (c) 零感知 |
| **Q3** | 账本模板 §四：(a) 厂家模板 / (b) 空白 / (c) 复制现有 |
| **Q4** | 账本可见性：是否支持"隐藏账本"（钱迹有，数据保留只是不显示）？ |
| **Q5** | 账本删除：删账本时连流水一起删（钱迹做法），还是流水转移到其他账本？ |
| **Q6** | 跨账本搜索：用户偶尔想"在所有账本里搜某关键字"，是否要做？ |
| **Q7** | 账本图标 / 颜色定制：影响视觉辨识度，是否做？ |
| **Q8** | 账本数量上限：单用户最多能建几个账本？是否限制？ |
| **Q9** | AI 端是否需要"账本归属"语义？AI 创建流水时落到哪个账本？ |
| **Q10** | 多账本数据导出：用户某天想把数据交付给将来的脚本，是否每个账本独立导出？还是合并？ |
| **Q11** | "默认账本"是否可以删除？还是必须始终保留至少一个？ |
| **Q12** | 共享数据（账户、收支动作）的"删除"在多账本场景下的语义：删除一个账户，影响所有账本吗？ |

## 七、风险

| 风险 | 缓解思路 |
|---|---|
| 数据模型大改，老数据迁移出错 | 升级前强制提示用户先做完整备份，迁移过程加日志、单测 |
| 用户对"账本"和"账户"概念混淆 | UI 文案 / 用户教育要明确（建议术语审一遍） |
| 隔离与共享的边界拍板后改主意成本高 | Q1 一定要彻底定下来，定下来后开发完不轻易变 |
| 切账本后找不到本期流水的混乱 | UI 上始终明显显示"当前账本：XXX" |
| 升级后存量用户感知混乱 | (c) 零感知策略 + 升级说明 |

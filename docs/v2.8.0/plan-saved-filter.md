## 〇、立项背景

来源：主管观察的产品薄弱点。讨论中用户拍板进 v2.8.0。

**用户痛点**：每次想看"上月餐饮支出""今年最大的几笔开销""用银行卡支付的"等常用条件，都要重新点筛选项 → 重复操作。

**目标**：让用户能保存筛选条件为"快捷视图"，一键回到。

---

## 一、功能本质

用户在流水页 / 统计页配置好一组**筛选条件**，能"另存为"一个**命名快速筛选**，后续一键即可应用。

### 与现有功能的关系

- 不替代现有"筛选面板"，是它的**扩展**
- 用户在筛选面板配完之后，多一个"保存为快捷"按钮
- 保存的快捷出现在某个明显的位置，一键应用

---

## 二、产品规则

### 2.1 筛选条件的范围（**待用户拍板**）

EasyAccounts 现有筛选维度（事实，非清单）：

| 维度 | 说明 |
|---|---|
| 时间范围 | 自定义日期 / 上月 / 本月 / 今年等 |
| 账户 | 多选 |
| 分类（一级 / 二级） | 多选 |
| 收支动作（action） | 收入 / 支出 / 转账 |
| 标签 | 多选 |
| 金额范围 | 最小值 / 最大值 |
| 关键字（备注搜索） | 文本 |
| 来源（from） | ai / mcp / Claw / scheduled / 用户手记 |

**Q1**：保存的快捷条件是否覆盖以上**全部维度**，还是只保存其中常用的几项？

主管建议：**全部维度都能保存**（数据结构简单，灵活性最大）。

### 2.2 时间范围特殊处理（**重要的产品规则**）

时间范围有两种保存语义：

| 模式 | 例子 | 用户体验 |
|---|---|---|
| **绝对时间** | "2026-03-01 ~ 2026-03-31" | 永远是 3 月那段 |
| **相对时间** | "上月" | 永远是当前的"上月"（动态） |

主管建议：**保存时按用户在表单里选的形式保存** —— 用户选了"上月" → 保存为相对；用户手填了具体日期 → 保存为绝对。**不引入额外开关**让用户在保存时选。

### 2.3 应用快捷的体验

- 用户在流水页 / 统计页有个"快捷筛选"入口（具体位置 UI 自决，前端 Claude 出方案）
- 列表展示用户保存的快捷（最近用 / 收藏的可置顶）
- 点击 → 立即应用条件，列表 / 统计自动更新
- 应用后用户能在筛选面板里看到当前生效的条件，可以**临时修改**（修改不影响保存的快捷本身）

### 2.4 管理快捷

- 改名
- 删除
- 改组合 / 重新保存（即"修改快捷"）—— 应用条件后调整 → 保存覆盖原快捷
- 排序 / 收藏 / 置顶（**Q2 待拍板**：是否需要）

## 三、各端交付目标（产品语言）

### 🟦 Server

1. 快捷条件 CRUD：创建 / 修改 / 删除 / 列表
2. 数据归属用户级（如未来做多账本，再考虑账本归属）
3. 时间范围支持"相对"语义（开发 Claude 自行决定如何存储相对/绝对的状态）

### 🟩 Web

1. 流水页 / 统计页的筛选面板 → 加"保存为快捷"按钮
2. 快捷列表入口：流水页明显位置展示
3. 快捷管理页：编辑 / 删除 / 改名 / 排序（按 Q2 决策）
4. 应用快捷后，UI 显眼提示"当前快捷：XXX，可以临时修改"

### 🟨 AI

**不在本版本范围**（AI 不感知用户保存的快捷，但用户可以让 AI 直接组合一个查询条件去查 —— 这是 AI 工具集已有能力，无需扩展）。

## 四、待用户拍板的产品问题

| # | 问题 |
|---|---|
| **Q1** | 快捷条件是否覆盖所有筛选维度？还是限定几项？ |
| **Q2** | 是否需要"收藏 / 置顶 / 排序"？（不做 = 用户存的快捷越多越乱；做 = 工作量略增） |

| **Q4** | 应用快捷后再修改，要不要给"另存为新快捷"的按钮？还是只能"覆盖原快捷"？ |
| **Q5** | 是否同时支持"流水页快捷"和"统计页快捷"两套？还是统一一套？ |

## 五、风险

| 风险 | 缓解思路 |
|---|---|
| 用户存了快捷但找不到入口 | 入口要醒目，初次用还可以加引导提示 |
| 多账本上线后（v2.8.0 同期），快捷条件归属哪个账本？ | 跟多账本的隔离规则保持一致 —— 在多账本 plan §二 Q1 一并对齐 |
| 时间范围"相对"和"绝对"的混淆 | UI 上对相对时间的快捷做明显提示（如"上月"标签） |

---

## 六、与多账本的协作

本功能与多账本（同 v2.8.0）的协作点：

- 快捷条件如果按多账本隔离 → 切账本时快捷列表也切换
- 如果共享 → 一份快捷在所有账本可用（但条件里如果含"分类"就尴尬，分类按多账本隔离）

→ **快捷条件应当与流水同隔离规则**（账本隔离），保持一致性。**确认入多账本 Q1 的对齐表**。

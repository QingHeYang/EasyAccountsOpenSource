### 1. Docker 部署适配 - 移除 .env 必需验证

#### 问题描述

Docker 环境中通过 compose 注入环境变量，不需要 `.env` 文件，但 `validate_paths()` 要求 `.env` 必须存在，导致容器启动失败。

```
错误: 文件不存在: /app/koalaq_hub_python/.env
配置路径验证失败 似乎无法启动
```

#### 解决方案

从 `required_files` 列表中移除 `.env`：

```python
# settings.py - validate_paths()
# 修改前
required_files = [self.env_file_path, self.agent_config_path, self.llm_config_path]

# 修改后
# .env 文件在 Docker 环境中不是必需的（通过 compose 注入环境变量）
required_files = [self.agent_config_path, self.llm_config_path]
```

**文件**: `koalaq_hub/config/settings.py`

### 2. 数据库版本迁移 - models 表重构

#### 问题描述

v2.6.0 重构了 `models` 表结构，旧版数据库缺少 `llm_config_name` 列，导致启动报错：

```
sqlite3.OperationalError: no such column: llm_config_name
```

#### 表结构对比

| 字段 | 旧版 | 新版 |
|------|------|------|
| 主键 | `model_id INTEGER AUTOINCREMENT` | `llm_id TEXT` |
| 新增 | - | `llm_config_name`, `api_key`, `url`, `temperature`, `top_p`, `max_tokens`, `description` |
| 唯一约束 | `UNIQUE(platform, model)` | `llm_config_name UNIQUE` |

#### 解决方案

添加自动迁移逻辑，检测旧表结构并重建：

```python
# database_connection.py - _init_tables()

# 1. 先执行建表语句
for script in ddl_scripts:
    cursor.execute(script)

# 2. 执行迁移（必须在索引创建之前）
migrations = [
    ("messages", "attachments", "TEXT DEFAULT ''"),
]
for table, column, definition in migrations:
    try:
        cursor.execute(f"ALTER TABLE {table} ADD COLUMN {column} {definition}")
    except sqlite3.OperationalError:
        pass

# 3. 检查 models 表兼容性，不兼容则重建
try:
    cursor.execute("SELECT llm_config_name FROM models LIMIT 1")
except sqlite3.OperationalError:
    self.logger.warning("检测到旧版 models 表结构，正在重建...")
    cursor.execute("DROP TABLE IF EXISTS models")
    cursor.execute("""CREATE TABLE models (...)""")

# 4. 最后创建索引（确保表结构正确）
for index in index_scripts:
    cursor.execute(index)
```

**关键点**：索引创建必须在迁移之后，否则会因缺少列而失败。

**文件**: `koalaq_hub/database/base/database_connection.py`

### 3. OpenAI Schema 兼容性修复 - array items

#### 问题描述

使用 gpt5-nano 等新模型时，函数调用报错：

```
Error code: 400 - Invalid schema for function 'flows':
In context=('properties', 'types'), array schema missing items.
```

新模型对 JSON Schema 校验更严格，array 类型必须有 `items` 定义。

#### 解决方案

**1. 修改 ToolParam 类，添加 items 属性：**

```python
# tools/base.py
@dataclass
class ToolParam:
    name: str
    param_type: str
    description: str
    required: bool = True
    enum: Optional[List[str]] = None
    default: Any = None
    items: Optional[Dict[str, Any]] = None  # 新增：array 元素类型

    def to_schema(self) -> Dict[str, Any]:
        schema = {
            "type": self.param_type,
            "description": self.description
        }
        if self.enum:
            schema["enum"] = self.enum
        if self.param_type == "object":
            schema["additionalProperties"] = True
        if self.param_type == "array":
            # array 类型必须有 items 定义
            schema["items"] = self.items or {"type": "string"}
        return schema
```

**2. 更新工具定义：**

```python
# tools/builtin/easy_accounts.py - flows 和 make_excel
ToolParam(
    name="types",
    param_type="array",
    description="分类ID列表",
    required=False,
    items={"type": "integer"}  # 新增
),
```

**文件**:
- `koalaq_hub/tools/base.py`
- `koalaq_hub/tools/builtin/easy_accounts.py`

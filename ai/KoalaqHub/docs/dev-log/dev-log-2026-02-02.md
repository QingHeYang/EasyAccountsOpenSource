## 今日开发内容

### 1. 新增 actions 工具

#### 问题描述

部分用户的分类（type）没有绑定 action，`types` 工具返回的 `actionId=null`。此时 LLM 无法获取正确的 actionId，导致记账失败。

#### 解决方案

新增 `actions` 工具，调用后端 `/action/getAction` 接口，返回所有可用的收支动作列表。

```python
@register_tool
@tool(name="actions", description=ACTIONS_DESC, parameters=[])
class ActionsTool(BaseTool):
    """获取收支动作列表"""

    async def execute(self, arguments, context):
        client = _get_client(context)
        url = f"{client.base_url}/action/getAction"

        async with httpx.AsyncClient() as http_client:
            response = await http_client.get(url, headers=client._build_headers())
            data = response.json().get("data", [])

            # 过滤禁用项，格式化输出
            result = []
            for action in data:
                if action.get("disable"):
                    continue
                result.append(
                    f"actionId={action.get('id')},name={action.get('hname')},handle={action.get('handle')}"
                )
            return self._success(result=json.dumps(result, ensure_ascii=False))
```

**返回示例**：
```json
["actionId=8,name=收入,handle=0", "actionId=9,name=支出,handle=1", "actionId=10,name=内部转账,handle=2", ...]
```

**工具描述**：
```python
ACTIONS_DESC = (
    "获取所有收支动作(action)列表。返回每个动作的ID、名称和收支类型(handle)。"
    "当分类(type)未绑定actionId时（即actionId=null），必须调用此工具获取正确的actionId。"
    "handle含义：0=收入，1=支出，2=内部转账。根据用户的收支意图选择对应handle的action。"
)
```

### 3. 重写任务指导提示词

#### 修改原因

原提示词未区分 typeId 和 actionId 的获取逻辑，也未涵盖分类未绑定 action 的场景。

#### 核心改动

1. **新增关键概念区分**：强调 typeId（"花在什么上"）和 actionId（"收还是支"）是完全不同的概念
2. **actions 工具加入工具表**：明确使用时机为 `actionId=null` 时
3. **添加流水步骤更新**：加入 actionId 为 null 时的分支处理
4. **查询流水补充**：handle 参数可按收入/支出/转账方向筛选
5. **不确定时的处理策略**：actionId 未知时先查 types，为 null 再调 actions

## 设计说明

### actionId 获取流程

```
types 工具返回分类数据
    ├── actionId 不为 null → 直接使用
    └── actionId 为 null → 调用 actions 工具
                              └── 根据 handle(0=收入/1=支出/2=转账) 选择对应 actionId
```

### handle 值含义

| handle | 含义 | 典型动作 |
|--------|------|----------|
| 0 | 收入方向 | 收入、借入、收钱 |
| 1 | 支出方向 | 支出、借出、还钱 |
| 2 | 内部转账 | 内部转账 |

---

## 备注

- actions 工具自动过滤 `disable=true` 的动作，只返回可用项
- 提示词中多处强调 typeId ≠ actionId，防止 LLM 混淆
- 所有修改向后兼容，已绑定 action 的分类不受影响

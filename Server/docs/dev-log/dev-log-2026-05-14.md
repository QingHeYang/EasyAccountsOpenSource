## 今日开发内容

### 1. 修 bug · combineTypeBean 一级分类金额覆盖

#### 问题描述

接口：`POST /analysis/v2/getAnalysisTypeList`，当 `combineSubType=true`（合并子分类到父分类）时出现。

代码位置：`AnalysisV2Service.java:111-136` 的 `combineTypeBean` 方法。

合并逻辑遍历 `dealMap.values()`：
- 子分类（`parentId != -1`）：累加金额到 parentMap[父id]，若父在 parentMap 中不存在则临时创建
- 一级分类自身（`parentId == -1`）：`parentMap.put(bean.getId(), bean)` **直接放入**

**Bug 在直接 put**：如果该一级分类的某个子分类先于它被遍历到，parentMap[id] 已被临时创建并累加金额；此时一级分类自身直接 put 会**覆盖**，丢失子分类已累加的部分。

HashMap 遍历顺序由 `hash & (capacity-1)` 决定的桶号顺序，由 typeId 大小决定。对同一份数据稳定（不是随机），但对不同用户、不同 typeId 范围结果不可预测。

#### 触发条件

三个条件同时成立：
1. 一级分类 `actionId=null`（v2.6.0 起允许的"通用容器"父分类，自身可直接记账）
2. 该一级分类**自身**有流水（用户直接挂父分类记账）
3. 该一级分类**子分类**也有流水

典型场景："借还"作为通用容器一级分类，下挂"借出"（支出）+ "还款"（收入）子分类：
- 用户偶尔直接挂"借还"懒记 100 元
- 挂"借出"记 80 元
- 挂"还款"记 50 元
- 合并子分类视图下"借还"应显示 230 元

实际表现取决于 typeId hash 顺序，可能显示 100、150、230 中的某一个，且对该用户**稳定错**。

#### 影响的接口范围

| 接口 | 受影响 |
|---|---|
| `/analysis/v2/getAnalysisTypeList` 当 `combineSubType=true` | ✅ 唯一受影响接口 |
| `/analysis/v2/getAnalysisTypeList` 当 `combineSubType=false` | ❌ 不走 combineTypeBean |
| `/analysis/v2/getAnalysisTypeMonthData` | ❌ 不走 combineTypeBean |
| `/analysis/doAnalysis` v1 同比/环比 | ❌ 独立的 AnalysisService |
| `/home/getHomeInfoV2/{year}` | ❌ 不涉及子分类合并 |

#### 解决方案

`else` 分支改为"已存在则累加，不存在则放入"：

```java
} else {
    // v2.7.0 修复 HashMap 顺序覆盖 bug
    AnalysisTypeListResponseDto.TypeBean existing = parentMap.get(bean.getId());
    if (existing == null) {
        parentMap.put(bean.getId(), bean);
    } else {
        BigDecimal existingMoney = new BigDecimal(existing.getMoney());
        BigDecimal currentMoney = new BigDecimal(bean.getMoney());
        existing.setMoney(existingMoney.add(currentMoney)
                .setScale(2, RoundingMode.HALF_UP).toString());
    }
}
```

修完后无论 HashMap 遍历顺序如何，结果都稳定正确。

### 2. v2 分析接口时间孔径放开到天级

#### 背景

前端反馈用户想看"精确到某一天"的分析饼图，原来 v2 两个分析接口（getAnalysisTypeList / getAnalysisTypeMonthData）的 `start`/`end` 入参只支持 `yyyy-MM` 月级精度，后端用 `DateUtils.buildFullDate` 自动填充为月初/月末。

#### 原行为

`DateUtils.buildFullDate` 只接受两段 `yyyy-MM`：
- `start` → `yyyy-MM-01`（月初 1 号）
- `end` → 该月最后一天；若是当前月，返回今天

非两段格式（含 `yyyy-MM-dd`）直接抛 `IllegalArgumentException`。

#### 新行为

`DateUtils.buildFullDate` 同时支持两段和三段：
- 三段 `yyyy-MM-dd` / `yyyy-M-d`：按字面日期返回，`isStartOfMonth` 参数忽略
- 两段 `yyyy-MM` / `yyyy-M`：保留原月初/月末逻辑

#### 代码实现

```java
public String buildFullDate(String yearMonthOrDate, boolean isStartOfMonth) {
    if (yearMonthOrDate == null) {
        throw new IllegalArgumentException("日期不能为空");
    }
    String input = yearMonthOrDate.trim();
    String[] parts = input.split("-");

    // 三段：yyyy-MM-dd 或 yyyy-M-d，直接按用户给定的日期返回
    if (parts.length == 3) {
        try {
            int y = Integer.parseInt(parts[0].trim());
            int m = Integer.parseInt(parts[1].trim());
            int d = Integer.parseInt(parts[2].trim());
            return LocalDate.of(y, m, d).format(DateTimeFormatter.ISO_LOCAL_DATE);
        } catch (NumberFormatException | DateTimeException e) {
            throw new IllegalArgumentException("无效的日期格式: " + input + "，应为 yyyy-MM-dd", e);
        }
    }

    // 两段：原 yyyy-MM 逻辑（月初/月末/当前月返回今天）
    if (parts.length != 2) {
        throw new IllegalArgumentException(
                "无效的日期格式: " + input + "，应为 yyyy-MM 或 yyyy-MM-dd");
    }
    // ... 原 yyyy-MM 逻辑保持不变
}
```

#### 兼容性

- 现有前端传 `yyyy-MM` 的调用行为完全不变
- 前端可按需升级到 `yyyy-MM-dd`，可以混传（如 `start=2026-05-10, end=2026-05-14`，或 `start=2026-05, end=2026-05-14`）
- 影响范围仅在 v2 分析两个接口（它们是 `buildFullDate` 的唯一调用方）

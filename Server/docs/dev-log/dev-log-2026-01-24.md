## 1. 数据库手动备份接口

### 1.1 需求背景

用户需要在恢复数据前手动备份当前数据，或随时触发备份。手动备份与自动备份逻辑一致，都会发送 WebHook（邮件通知）。

### 1.2 接口设计

```
POST /backup/backup
```

**成功响应：**
```json
{
  "code": 0,
  "msg": "Success",
  "data": "yd_jz_manual_20260124_1530.sql"
}
```

### 1.3 文件名区分

| 类型 | 文件名格式 | 示例 |
|------|-----------|------|
| 自动备份 | `yd_jz_时间戳.sql` | `yd_jz_20260124_2200.sql` |
| 手动备份 | `yd_jz_manual_时间戳.sql` | `yd_jz_manual_20260124_1530.sql` |

### 1.4 流程

1. 生成备份文件名（带 `manual` 标识）
2. 执行 `mysqldump` 命令
3. 发送 WebHook（邮件通知）
4. 返回文件名

## 2. 数据库恢复接口

### 2.1 需求背景

用户重新部署系统后，需要恢复之前备份的数据。此时服务器上没有备份文件，用户需要手动上传 SQL 备份文件进行恢复。

### 2.2 实现方案

| 方案 | 说明 |
|------|------|
| CMD 方式 | 使用 `mysql` 命令导入，Dockerfile 已安装 `mysql-client` |
| 上传恢复 | 用户上传 SQL 文件 → 保存到备份目录 → 执行恢复命令 |

### 2.3 接口设计

```
POST /backup/restore
Content-Type: multipart/form-data
参数: file (SQL 备份文件)
```

**流程：**
1. 用户上传 `.sql` 备份文件
2. 校验文件格式
3. 保存到 `/Ledger/backup/` 目录
4. 执行 `mysql` 命令恢复数据

### 2.4 配置变更

**application-server.properties：**

```properties
# 恢复命令
sqlRestoreCmd=/usr/bin/mysql -h ${MYSQL_HOST:db} -P ${MYSQL_PORT:3306} -u${MYSQL_USERNAME:root} -p${DB_PASSWORD:easy_accounts} yd_jz <
```

### 2.5 代码实现

**BackupService.java：**

```java
public void uploadAndRestore(MultipartFile file) {
    // 1. 校验文件
    if (file == null || file.isEmpty()) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "请上传备份文件");
    }

    String originalName = file.getOriginalFilename();
    if (originalName == null || !originalName.endsWith(".sql")) {
        throw new BusinessException(ErrorCode.PARAM_ERROR, "请上传 .sql 格式的备份文件");
    }

    // 2. 保存文件到备份目录
    String filePath = backupFolder + originalName;
    file.transferTo(new File(filePath));

    // 3. 执行恢复命令
    String[] cmd = new String[]{"/bin/sh", "-c", restoreCmd + filePath};
    Process process = Runtime.getRuntime().exec(cmd);
    int exitCode = process.waitFor();

    if (exitCode != 0) {
        throw new BusinessException(ErrorCode.SYSTEM_ERROR, "恢复失败");
    }
}
```

**BackupController.java：**

```java
@PostMapping("/restore")
public BaseDto restore(@RequestParam("file") MultipartFile file) {
    backupService.uploadAndRestore(file);
    return BaseDto.setSuccessBean();
}
```

### 2.6 前端调用示例

```javascript
// 手动备份
await fetch('/api/backup/backup', { method: 'POST' });

// 恢复
const formData = new FormData();
formData.append('file', sqlFile);
await fetch('/api/backup/restore', { method: 'POST', body: formData });
```

### 2.7 设计决策

| 决策 | 理由 |
|------|------|
| 使用 CMD 而非 JDBC | Dockerfile 已有 mysql-client，原生支持更好 |
| 上传而非选择 | 重新部署场景下服务器没有备份文件 |
| 不记录数据库日志 | 恢复后日志会被覆盖，无意义 |
| 保存上传文件 | 上传的备份文件保留，方便后续使用 |
| 手动备份加 manual 标识 | 区分自动备份和手动备份文件 |
| 手动备份发送 WebHook | 与自动备份逻辑一致，发送邮件通知 |

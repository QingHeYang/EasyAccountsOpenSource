## 1. API 错误处理体系优化

### 1.1 问题背景

所有业务异常（余额不足、分类校验等）都返回 HTTP 500，客户端/监控误以为服务端一直报错。

### 1.2 解决方案

创建统一的异常处理体系：

| 文件 | 说明 |
|------|------|
| `exception/ErrorCode.java` | 错误码枚举 |
| `exception/BusinessException.java` | 业务异常类 |
| `exception/GlobalExceptionHandler.java` | 全局异常处理器 |
| `dto/BaseDto.java` | 添加 error() 便捷方法 |

### 1.3 错误码规范

```
0       - 成功
40xxx   - 参数校验错误
401/418 - 认证错误（保持不变）
42xxx   - 业务规则错误
44xxx   - 资源不存在
50xxx   - 系统错误
```

### 1.4 Service 改造

检查全部 13 个 Service，只有 FlowService 有 `throw new Exception`，已改为 `BusinessException`：

| 位置 | 错误码 |
|------|--------|
| 分类有子分类（2处） | `ErrorCode.TYPE_HAS_CHILDREN` (42002) |
| 余额不足（2处） | `ErrorCode.INSUFFICIENT_BALANCE` (42001) |

## 4. MySQL 镜像优化

### 4.1 目录结构

```
Server/MySQL/
├── Dockerfile
└── yd_jz_base.sql      # 打进镜像
```

### 4.2 Dockerfile

```dockerfile
FROM mysql:8.0.31
LABEL maintainer="Mecy@deep-blue.cloud"
COPY yd_jz_base.sql /docker-entrypoint-initdb.d/
ENV MYSQL_DATABASE=yd_jz
ENV LANG=C.UTF-8
```

### 4.3 使用方式

- **首次部署**：直接启动，镜像内 SQL 自动初始化
- **恢复数据**：取消 compose 中 init 映射注释，放入备份 SQL，删除 data 目录，重启

## 5. Version API 增强

### 5.1 需求背景

前端需要获取更多配置信息，包括登录配置和备份状态。

### 5.2 API 响应结构

```json
{
  "versions": {
    "fontBranch": "4.0.0",
    "backendBranch": "2.5.1",
    "mysqlBranch": "2.5.0",
    "agentBranch": "1.1.0",
    "webhookBranch": "1.0.0",
    "release": "2.6.0"
  },
  "auth": {
    "enable": true,
    "expiredMinutes": 30,
    "singleLogin": true
  },
  "backup": {
    "cron": "00 00 22 * * ?",
    "valid": true,
    "description": "已配置自动备份"
  }
}
```

### 5.3 备份状态说明

| 情况 | valid | description |
|------|-------|-------------|
| 未配置 | false | 未配置备份时间 |
| 配置有效 | true | 已配置自动备份 |
| 配置无效 | false | cron表达式无效: {错误信息} |

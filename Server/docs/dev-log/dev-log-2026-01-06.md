## 今日开发内容

### 1. Log4j2 滚动日志优化

#### 1.1 问题背景

滚动日志文件 `app-rolling-*.log` 从 9 月份一直保留到当前，没有自动删除旧文件。

**原因：** `DefaultRolloverStrategy` 的 `max="20"` 只控制同一天内因大小滚动产生的文件数量（`%i` 索引），不会删除按日期滚动的旧文件。

#### 1.2 解决方案

添加 `Delete` 操作 + `OnStartupTriggeringPolicy`：

```xml
<Policies>
    <OnStartupTriggeringPolicy/>
    <TimeBasedTriggeringPolicy/>
    <SizeBasedTriggeringPolicy size="10MB"/>
</Policies>
<DefaultRolloverStrategy max="20">
    <Delete basePath="${log-path}" maxDepth="1">
        <IfFileName glob="app-rolling-*.log"/>
        <IfLastModified age="P10D"/>
    </Delete>
</DefaultRolloverStrategy>
```

| 配置项 | 说明 |
|--------|------|
| `OnStartupTriggeringPolicy` | 启动时触发滚动和删除 |
| `IfLastModified age="P10D"` | 删除 10 天前的日志（ISO 8601 格式） |

### 2. Token 认证并发修复

#### 2.1 问题背景

并发请求时，部分请求返回 418 认证失败：

```
17:24:26 exec-2: 请求 /action/getAction，token: 0534658e...
17:24:26 exec-3: 请求 /account/getAccount，同一个 token
17:24:26 exec-3: 认证失败 418 ❌
17:24:26 exec-2: Token 滑动刷新 ✅
```

**原因：** `AuthUtils.isTokenValid()` 文件读写没有加锁，并发时读到不完整数据导致 `Auth.decode()` 返回 null。

#### 2.2 解决方案

采用**双重保护**策略：

**1. synchronized 锁保护**

```java
private static final Object FILE_LOCK = new Object();

private int isTokenValid(String token) {
    synchronized (FILE_LOCK) {
        // 读取、验证、写入都在锁内
    }
}
```

**2. 减少刷新频率**

只在剩余时间 < 50% 时才执行滑动刷新，大幅减少写操作：

```java
long remainingTime = auth.getExpireTime() - currentTime;
if (remainingTime < totalDuration / 2) {
    // 才执行写入
    saveAuth(auth);
}
```

### 3. 分析统计 API 修复

#### 3.1 问题背景

两个 API 返回数据不一致：

- `getAnalysisTypeList` 返回 typeId=58 收入 7000.00
- `getAnalysisTypeMonthData` 查询 typeId=58 返回 totalIncome=0.00

#### 3.2 原因分析

`getAnalysisTypeMonthData` 当查询父分类时：

```java
// 原代码：有子分类时只查子分类，漏掉了父分类自己的流水
if (types == null || types.isEmpty()) {
    flows = flowRepository.findByFDateBetweenAndType(..., type.getId());
} else {
    for (Type subType : types) {
        flows.addAll(flowRepository.findByFDateBetweenAndType(..., subType.getId()));
    }
    // ❌ 父分类自己的流水被漏掉了！
}
```

#### 3.3 解决方案

```java
// 先查父分类自己的流水
flows = flowRepository.findByFDateBetweenAndType(startDate, endDate, type.getId());
// 再查子分类的流水
List<Type> subTypes = typeRepository.findByParent(type.getId());
if (subTypes != null && !subTypes.isEmpty()) {
    for (Type subType : subTypes) {
        flows.addAll(flowRepository.findByFDateBetweenAndType(startDate, endDate, subType.getId()));
    }
}
```

### 4. 记账分类校验

#### 4.1 问题背景

虽然前端限制了有子分类的父分类不能直接记账，但后端没有校验，导致脏数据可能进入数据库。

#### 4.2 解决方案

在 `doAddFlow` 和 `doUpdateFlow` 添加校验：

```java
// 校验分类：有子分类的父分类不允许直接记账
List<Type> subTypes = typeRepository.findByParent(flowAddRequestDto.getTypeId());
if (subTypes != null && !subTypes.isEmpty()) {
    throw new Exception("该分类有子分类，请选择子分类记账");
}
```

**修改文件：** `FlowService.java`

| 方法 | 说明 |
|------|------|
| `doAddFlow` | 新增流水时校验 |
| `doUpdateFlow` | 更新流水时校验 |

## 技术要点

### Log4j2 Delete age 格式

使用 ISO 8601 Duration 格式：

| 格式 | 含义 |
|------|------|
| `P10D` | 10 天 |
| `P30D` | 30 天 |
| `PT12H` | 12 小时 |

### synchronized 锁的性能影响

| 场景 | 影响 |
|------|------|
| 大部分请求 | 只读不写，锁持有时间极短（毫秒级） |
| 刷新请求 | 需要写文件，仅在剩余 < 50% 时触发 |

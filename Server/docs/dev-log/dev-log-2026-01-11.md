## 2. 内部转账 exemptMode

### 2.1 需求背景

原有设计中，内部转账的 exempt 是统一的：两个账户要么都 exempt，要么都不 exempt。

实际场景需要更精细的控制：

| 场景 | 期望行为 |
|------|----------|
| 还信用卡 | 银行卡 → 信用卡，**只有信用卡**的 exemptMoney 变化 |
| 转入理财 | 活期 → 理财，**只有理财**的 exemptMoney 变化 |

### 2.2 字段定义

| 值 | 含义 | 转出账户 exempt | 转入账户 exempt |
|----|------|-----------------|-----------------|
| 0 | 都不 exempt（默认） | false | false |
| 1 | 转出账户 exempt | true | false |
| 2 | 转入账户 exempt | false | true |
| 3 | 两边都 exempt | true | true |

### 2.3 数据库变更

```yaml
# yd_jz_2.6.0.yaml
- addColumn:
    tableName: action
    columns:
      - column:
          name: exempt_mode
          type: INT
          defaultValueNumeric: 0
          constraints:
            nullable: false

# 数据迁移：内部转账且 exempt=true 的设置 mode=2（还信用卡场景）
- sql:
    sql: UPDATE action SET exempt_mode = 2 WHERE handle = 2 AND exempt = true
```

### 2.4 代码变更

| 文件 | 修改 |
|------|------|
| `entity/Action.java` | 新增 exemptMode 字段 |
| `service/FlowService.java` | setNewFlow/doUpdateFlow/doDeleteFlow 处理 exemptMode |

### 2.5 FlowService 核心逻辑

```java
case ContentValues.ACTION_INNER:
    toAccount = accountService.getOriginAccountById(flowAddRequestDto.getAccountToId());
    // v2.6.0: 根据 exemptMode 决定哪个账户 exempt
    int exemptMode = action.getExemptMode() != null ? action.getExemptMode() : 0;
    boolean toAccountExempt = (exemptMode == 2 || exemptMode == 3);
    boolean fromAccountExempt = (exemptMode == 1 || exemptMode == 3);
    toAccount = handleAccount(ACTION_ADD, money, toAccount, toAccountExempt);
    account = handleAccount(ACTION_SUB, money, account, fromAccountExempt);
    break;
```

### 2.6 接口变更

| 接口 | 变更 |
|------|------|
| `POST /action/addAction` | 请求新增 `exemptMode`（可选，默认0） |
| `PUT /action/updateAction/{id}` | 请求新增 `exemptMode`（可选） |
| `GET /action/getAction` | 响应新增 `exemptMode` |
| `GET /action/getAction/{id}` | 响应新增 `exemptMode` |

### 2.7 设计决策

**Q: 为什么不在 Flow 表存 exemptMode？**

A: 用户决定接受「从 Action 读取 exemptMode」的风险。理由：
- Action 配置很少变化
- 不属于常规操作
- 保持 Flow 表简洁

# 分类记账校验逻辑优化

## 需求背景

当前 `FlowService.java` 中的分类校验逻辑过于简单，只判断了是否有子分类，没有考虑分类是否绑定了收支行为（actionId）。

## 业务逻辑

### 分类与收支的关系

1. **父级分类没定义 actionId** → 可以被任意收支选中，**可以直接记账**
2. **父级分类定义了 actionId** → 子分类继承收支，**应该选子分类记账**

### 校验流程

```
用户选择分类
      │
      ▼
┌──────────────┐
│ 该分类有子分类？│
└──────┬───────┘
       │
 ┌─────┴─────┐
有           无
 │            │
 ▼            ▼
┌──────────┐  ┌──────────┐
│定义了     │  │ 允许记账  │
│actionId？│  └──────────┘
└────┬─────┘
     │
  ┌──┴──┐
 有    无
  │     │
  ▼     ▼
拒绝   允许
记账   记账
```

## 当前代码问题

**文件**: `FlowService.java`
**位置**: 第 60-64 行（doAddFlow）和第 139-142 行（updateFlow）

```java
// 当前逻辑（有问题）
List<Type> subTypes = typeRepository.findByParent(flowAddRequestDto.getTypeId());
if (subTypes != null && !subTypes.isEmpty()) {
    throw new BusinessException(ErrorCode.TYPE_HAS_CHILDREN, "该分类有子分类，请选择子分类记账");
}
```

**问题**: 只判断了"有无子分类"，没有判断"是否定义了 actionId"

## 修改方案

```java
// 正确逻辑
List<Type> subTypes = typeRepository.findByParent(flowAddRequestDto.getTypeId());
if (subTypes != null && !subTypes.isEmpty()) {
    // 获取当前分类
    Type currentType = typeRepository.findById(flowAddRequestDto.getTypeId()).orElse(null);
    // 只有定义了 actionId 的父分类才需要选子分类
    if (currentType != null && currentType.getActionId() != null) {
        throw new BusinessException(ErrorCode.TYPE_HAS_CHILDREN, "该分类有子分类，请选择子分类记账");
    }
}
```

## 对照表

| 场景 | 当前逻辑 | 正确逻辑 |
|------|---------|---------|
| 有子分类 + 定义了 actionId | 拒绝 | 拒绝（选子分类） |
| 有子分类 + 没定义 actionId | 拒绝 | **允许记账** |
| 无子分类 | 允许 | 允许 |

## 注意事项

- 需要同时修改 `doAddFlow()` 和 `updateFlow()` 两处
- 注意 actionId 可能是 null 或特殊值（如 -1），需要确认具体判断条件

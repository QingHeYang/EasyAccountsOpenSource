#### 关键决策细节

**Element Plus 的 `el-button :icon` 不能直接传 Lucide**：EP 的 IconProps 类型不接受任意 component。改用 slot 写法：
```vue
<el-button circle><ClipboardClock :size="16" /></el-button>
```
而不是 `<el-button :icon="ClipboardClock" />`。

**Vant `van-cell icon=` prop 同理**：只接受字符串名（Vant 内置图标），用 `<template #icon>` slot：
```vue
<van-cell title="收支">
  <template #icon><ArrowLeftRight class="cell-icon" /></template>
</van-cell>
```

**垂直对齐"偏上"**：Lucide 是 SVG 元素默认 `display: inline`，会按文字 baseline 对齐 → 在 cell flex 容器里跟文字一起放时往往看起来"偏上"。修复：
```css
.cell-icon {
  display: block;       /* 关键：脱离 inline baseline */
  align-self: center;
}
```

**stroke-width 默认 1.75**：Lucide 原生 default 是 2，跟 Vant 字体图标比偏粗。统一调到 1.75 跟两端 UI 库视觉重量平衡。

**颜色机制**：所有 Lucide 组件**永不传 `:color` prop**，全靠父级 CSS `color` 属性继承（`stroke="currentColor"`）。这样：
- 主题切换、暗黑模式、active / hover / disabled 状态都靠 CSS 切换 `color` 即可
- 项目原有 `.cell-icon { color: var(--color-text-secondary); }` 等 CSS 一行不用改

**淡红色退出登录**：单独一个 `.cell-icon-danger` 类（`#ff7875` 亮 / `#ff9999` 暗），仅用于"危险/破坏性"操作。

### 4. toast 体验全面优化

#### 起源
用户："月度 excel 提醒，邮件提醒这个，如果没配置，会有一个 toast 出现，但是显示的有点太高了，并且时间飞快就过去了"
→ 给后端响应 `{code: 42017, msg: "邮件 SMTP 未配置完整，无法启用邮件功能..."}`
→ "不对，就快速的跑了 0.5s 都不到"

#### 根因
**业务 catch 抢关全局 fail toast**：

```ts
} catch (err) {
  closeToast()              // ← bug！把全局 onError 弹的 fail toast 秒关
  if (!isHandledError(err)) showToast('保存失败')
}
```

时序：
1. 后端返 42017
2. `request.ts` 拦截器 → `globalHandlers.onError(code, msg)` → `showFailToast(msg)`
3. 拦截器抛 `ApiError(handled=true)`
4. 业务 catch 进入 → **`closeToast()` 立刻把 fail toast 秒关**
5. `isHandledError(err) === true`，跳过 showToast

业务 toast 弹出到被关之间约 0.5 秒，跟用户描述完全吻合。

#### 修复（9 处）

5 个 system settings 子页 + ScheduledFlowAdd 4 个 catch，统一改成：
```ts
} catch (err) {
  if (!isHandledError(err)) {
    closeToast()
    showToast('xxx 失败')
  }
  // handled error：全局 onError 已弹 fail toast，让它自然显示
}
```

文件清单：
- ReminderSettings.onSave
- AutoExcelSettings.onSave + runNow
- MailSettings.onSave + testMail
- AuthSettings.onSave
- BackupSettings.onSave
- ScheduledFlowAdd.onSubmit 主 catch
- ScheduledFlowAdd.onSubmit 内部 startRule 子 catch
- ScheduledFlowAdd.loadEditingRule
- ScheduledFlowAdd.onDelete

#### 长文本 toast 横长条优化

**问题**：Vant `showFailToast` 默认是 90×90 方形 + 大叉号 icon + 文字，遇到 50 字"邮件 SMTP 未配置完整..."这种长文案被压成多行不成形。

**方案**：根据文案长度切 toast 类型：

```ts
onError: (_code, msg) => {
  const text = msg ?? ''
  if (text.length > 20) {
    // 长文案：横长条 + 88% 宽度 + 文字左对齐
    showToast({
      message: text,
      type: 'fail',
      position: 'bottom',
      duration: Math.min(2000 + Math.floor(text.length / 10) * 500, 5000),
      className: 'app-long-toast',
    })
  } else {
    // 短文案：方形 fail toast 视觉强调
    showFailToast({ message: text, position: 'bottom' })
  }
}
```

**`.app-long-toast` 样式**（mobile/styles/base.css）：
```css
.van-toast.app-long-toast {
  max-width: 88% !important;
  width: auto !important;
  min-height: auto !important;
  padding: 14px 18px !important;
  flex-direction: row !important;  /* 关键：横向 */
  align-items: center !important;
}

.van-toast.app-long-toast .van-toast__text {
  text-align: left !important;
  word-break: break-word;
  line-height: 1.5;
}
```

**duration 按字数线性增加**：base 2s + 每 10 字 +500ms，封顶 5s。50 字文案 = 4500ms 刚够看完。

#### 其他全局调整
- `position: 'middle'` → `'bottom'`：跟操作位置（开关 / 按钮）更近，不挡顶部 header

## 遇到的坑 / 注意事项

### 1. closeToast() 跟全局 fail toast 同实例抢关
（part3 / 5-05 part2 / 本次都遇到）—— Vant Toast 是单例，业务代码 catch 里 closeToast 会把全局 onError 弹的 fail toast 秒关。**正确姿势**：success 才关 loading toast，error 让全局接管，本地仅在 `!isHandledError` 时兜底。

### 2. Element Plus el-button :icon 不接受 Lucide 组件
EP 的 IconProps 类型只接受 EP 自家 icon 组件。Lucide 用 slot 写法，并补 `.btn-icon { margin-right: 6px }` 因为 EP 的 `[class*="el-icon"] + span` 间距规则不会作用到 Lucide。

### 3. Vant van-cell `icon=` prop 只接受字符串
内置图标名映射，不能传组件。Lucide 用 `<template #icon>` slot。

### 4. Lucide SVG `display: inline` 默认偏上
按文字 baseline 对齐 → flex 容器里跟文字一起放视觉偏上。`display: block` + `align-self: center` 解决。

### 5. Vant fail toast 是方形 90×90
长文案塞进去会被压成多行不成形。要么切 type 'text'（失去 fail icon 语义），要么 className 重写样式（本次方案）。

### 6. 移动端横向滚动 `overflow-x: auto` 失效
父级 `overflow: hidden` 双向时移动端 swipe 可能被吃掉。改父级 `overflow-x: visible; overflow-y: hidden;` + 子元素加 `touch-action: pan-x` + `-webkit-overflow-scrolling: touch`。

### 7. 已删除 `cascaderValue` 字段从 store 也要同步删除
（5-05 part2 已遇到 flowAddState）—— 抽组件后 store 接口不能保留无用字段。

3. **状态符号（CircleCheckFilled / CircleCloseFilled / WarnFilled）保留 EP**：Lucide 没有等价的"实心圆 + 勾/叉"语义图标
4. **AutoExcel 提醒确认弹窗时机**（part1 留下）：等后端提供"配置就绪检测"接口后，邮件提醒开关的 confirm 改成"未配置时才弹"
5. **Setting 主页"NEW"标签**：用户决定不做（自然发现新功能即可），永久关闭

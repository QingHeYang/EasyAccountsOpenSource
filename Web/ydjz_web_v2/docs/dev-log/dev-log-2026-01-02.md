## 今日开发内容

### 1. 问题背景

移动端页面跳转后，筛选条件会丢失：

| 场景 | 问题 |
|------|------|
| 统计 → 分类统计 → 返回 | 月份筛选重置 |
| 明细 → FlowAdd → 返回 | 月份和筛选条件丢失 |
| 分类统计 → 流水 popup → FlowAdd → 返回 | popup 关闭，筛选重置 |

### 2. 解决方案

使用 **Pinia Store** 保存页面状态，配合 `sessionStorage` 标记页面来源。

#### 2.1 核心模式

```typescript
// 1. 创建状态 Store
export const useXxxFilterStore = defineStore('xxxFilter', () => {
  const state1 = ref(...)
  const state2 = ref(...)
  const initialized = ref(false)

  function save(state: {...}) {
    // 保存所有状态
    initialized.value = true
  }

  function reset() {
    // 重置所有状态
    initialized.value = false
  }

  return { state1, state2, initialized, save, reset }
})

// 2. 页面中使用
onMounted(() => {
  if (filterStore.initialized) {
    // 恢复状态
  } else {
    // 初始化
  }
})

onBeforeUnmount(() => {
  filterStore.save({...})
})
```

#### 2.2 跨页面来源判断

使用 `sessionStorage` 标记页面来源，避免 `router.replace` 产生多余历史记录：

```typescript
// 来源页面（Analysis.vue）
function toTypeDetail(typeId: number) {
  sessionStorage.setItem('analysisTypeFrom', 'analysis')
  router.push({ path: '/analysis/type', query: {...} })
}

// 目标页面（AnalysisType.vue）
onMounted(() => {
  const isFromAnalysis = sessionStorage.getItem('analysisTypeFrom') === 'analysis'
  sessionStorage.removeItem('analysisTypeFrom')  // 立即清除

  if (isFromAnalysis) {
    // 从统计进入，使用路由参数
    filterStore.reset()
    initDateRange()
  } else if (filterStore.initialized) {
    // 从 FlowAdd 返回，恢复 store 状态
  }
})
```

## 技术要点

### 为什么不用 URL 参数标记来源？

最初尝试在 URL 中添加 `from=analysis` 参数，然后用 `router.replace` 删除。但发现：

1. `router.replace` 在 `onMounted` 中执行会产生额外的历史记录
2. 导致点击返回时需要点两次

改用 `sessionStorage` 后：
- 跳转前设置标记
- 目标页面读取并立即删除
- 不影响路由历史

### Pinia Store vs Vuex

本项目使用 Pinia 作为状态管理：
- 更简洁的 API
- 更好的 TypeScript 支持
- 无需 mutations，直接修改状态

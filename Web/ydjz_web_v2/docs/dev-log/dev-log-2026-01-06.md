### 3. 全局错误拦截优化

#### 3.1 问题描述

之前的错误处理存在以下问题：

| 问题 | 表现 |
|------|------|
| 认证错误提示不友好 | 显示 "xxx失败" 而非 "登录已过期" |
| 错误码暴露给用户 | 显示 `42001: 余额不足` |
| 业务代码无法区分错误类型 | catch 中无法判断是认证错误还是业务错误 |

#### 3.2 解决方案

**新增 ApiError 类：**

```typescript
export class ApiError extends Error {
  code: number           // 错误码
  isAuthError: boolean   // 是否为认证错误
  handled: boolean       // 是否已全局处理

  constructor(code: number, message: string, isAuthError = false, handled = false) {
    super(message)
    this.name = 'ApiError'
    this.code = code
    this.isAuthError = isAuthError
    this.handled = handled
  }
}
```

**新增工具函数：**

```typescript
// 判断是否为认证错误
export function isAuthError(error: unknown): boolean {
  return error instanceof ApiError && error.isAuthError
}

// 判断是否已被全局处理
export function isHandledError(error: unknown): boolean {
  return error instanceof ApiError && error.handled
}
```

**响应拦截器重构：**

```typescript
// 认证错误码
const AUTH_ERROR_CODES = [401, 418, 4010, 4011]

instance.interceptors.response.use(
  (response) => {
    const { code, msg } = response.data

    // 成功
    if (code === 0) return response

    // 认证错误 - reject 并标记
    if (AUTH_ERROR_CODES.includes(code)) {
      if (code === 401 || code === 418) {
        localStorage.removeItem('token')
      }
      globalHandlers.onUnauthorized?.(code)
      return Promise.reject(new ApiError(code, '登录已过期，请重新登录', true, true))
    }

    // 业务错误 - 调用全局错误回调后 reject
    globalHandlers.onError?.(code, msg)
    return Promise.reject(new ApiError(code, msg, false, true))
  },
  (error) => {
    const status = error.response?.status
    const msg = error.response?.data?.msg || error.message || '网络错误'

    // HTTP 401/418
    if (status === 401 || status === 418) {
      localStorage.removeItem('token')
      globalHandlers.onUnauthorized?.(status)
      return Promise.reject(new ApiError(status, '登录已过期，请重新登录', true, true))
    }

    // 其他 HTTP 错误
    globalHandlers.onError?.(status || 0, msg)
    return Promise.reject(new ApiError(status || 0, msg, false, true))
  }
)
```

**错误提示优化：**

```typescript
// main-desktop.ts / main-mobile.ts
onError: (_code, msg) => {
  // 只显示消息，不显示错误码
  ElMessage.error(msg)  // 或 showNotify({ message: msg })
}
```

#### 3.3 业务代码用法

业务代码可以使用 `isAuthError()` 判断是否需要显示错误提示：

```typescript
import { isAuthError } from '@shared/api'

try {
  await flowApi.delete(id)
  showToast('删除成功')
} catch (err) {
  // 认证错误已由拦截器处理（跳转登录页），不需要显示"删除失败"
  if (!isAuthError(err)) {
    showToast('删除失败')
  }
}
```

## 技术要点

### 1. 错误处理分层

```
响应返回
  ├── code === 0 → 返回响应（业务代码正常处理）
  ├── 认证错误 → reject ApiError(isAuthError=true)
  │              ├── 全局处理：跳转登录页
  │              └── 业务代码：可用 isAuthError() 判断，忽略显示
  └── 业务错误 → reject ApiError(handled=true)
                 ├── 全局处理：显示错误提示
                 └── 业务代码：可选择是否额外处理
```

### 2. 移动端隐私模式与桌面端差异

| 功能 | 桌面端 | 移动端 |
|------|--------|--------|
| 账户按钮 | 可点击（弹窗内金额也隐藏） | 禁用点击 |
| 图表按钮 | 显示蒙版遮罩 | 禁用点击 |
| 原因 | 桌面端空间大，可显示蒙版 | 移动端交互简化 |

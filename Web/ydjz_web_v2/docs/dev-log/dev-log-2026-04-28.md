### 1. 新增 `systemConfig.ts` API 模块（5 域 + overview）

#### 背景

v2.7.0 后端把所有"管理员级配置"统一收口到 `/system/config/*` 下，分 5 个域：
- `mail`（SMTP / 端口 / 发件人 / 授权码 / 收件人 / 全局开关）
- `backup`（自动 SQL 备份调度）
- `auth`（登录开关 / 单点 / token 时长）
- `scheduledFlow`（定时记账事前提醒）—— 从旧 `/scheduledFlow/config/reminder` 迁来
- `autoExcel`（自动月度 Excel + 提前提醒）—— 全新

所有 PUT 都是 partial。`/system/config/overview` 聚合接口一次拿 5 域 humanReadable 摘要，用于设置首页。

#### 关键设计

```ts
export const systemConfigApi = {
  getOverview() { /* 5 域聚合 */ },

  /* mail */
  getMail() / updateMail(partial) / testMail() / testAllMails(),

  /* backup */
  getBackup() / updateBackup(partial),

  /* auth */
  getAuth() / updateAuth(partial),

  /* scheduledFlow */
  getScheduledFlow() / updateScheduledFlow(),  /* 类型 ReminderConfig 沿用 scheduledFlow.ts */

  /* autoExcel */
  getAutoExcel() / updateAutoExcel(partial)
    / runAutoExcelNow()           /* 不等下次 cron，立刻执行 */
    / sendAutoExcelReminderNow(), /* 走防重逻辑 */
}
```

类型注释里把所有约束都写进了 JSDoc，避免分散到文档：
- `mail.password`：`null/undefined`=不动，`""`=清空，其它=明文（后端加密入库）
- `backup.dayOfWeek`：1-7 ISO（周一=1），UI 转换要注意
- `backup.dayOfMonth`：1-28（防 2 月跳月）
- `autoExcel.target`：字符串枚举 `LAST_MONTH` / `CURRENT_MONTH`（不是 0/1 数字）
- `autoExcel.remindEmailEnabled`：`remindEnabled=false` 时忽略；开启时站内必发，邮件按这个开关

#### `index.ts` 类型 alias 防冲突

`home.ts` 已导出 `AuthConfig` / `BackupConfig`（旧 `/home/getVersion` 字段约定，结构与 v2.7.0 不同），systemConfig 也叫这两个名字。处理：

```ts
export type {
  BackupConfig as SystemBackupConfig,
  AuthConfig as SystemAuthConfig,
  /* ... */
} from './systemConfig'
```

让旧代码继续用 `home.ts` 的命名，新代码导入时显式 `SystemAuthConfig` 区分。

#### 数据流：父级 overview 单向下发，子级单项 update 后 emit `'updated'` 让父级 reload

```
SystemSettings (父)
  ├── watch visible → systemConfigApi.getOverview()
  └── overview.value = res.data.data
        ↓ props
  ├── <AuthSection :data="overview.auth" @updated="onSectionUpdated" />
  ├── <MailSection :data="overview.mail" @updated="..." />
  ├── ...
        ↑ emit('updated')
  父：onSectionUpdated() → 重新 getOverview → props 进来 → 子组件 watch(props.data) → 同步本地 ref

```

这套机制顺手解决了第一版"会话时长改完后页面没回填"的 bug —— 因为更新 → reload → props 进来 → 子组件 watch 同步本地 ref，闭环。

#### 子组件本地 ref + watch props 同步（防 debounce 期间被覆盖）

为什么子组件不直接绑 `:model-value="props.data.xxx"`？因为 InputNumber debounce 期间用户继续输入，外部 props 还没变，但如果有别的 emit 触发 reload，`:model-value` 会被新 props 覆盖、丢用户编辑。

所以子组件用：
```ts
const localTokenMinutes = ref(props.data.tokenExpiredMinutes)
watch(() => props.data, (v) => { localTokenMinutes.value = v.tokenExpiredMinutes })
```

只有"成功 PUT → emit('updated') → 父级 reload"这条路径才会同步本地。debounce 期间外部 props 不变（因为没人 reload），不会覆盖。

### 7. 邮件设置：授权码已设隐藏输入框 + 大清除按钮 + info popover

授权码字段三态：

| 状态 | UI |
|---|---|
| **已设置** | "已设置"绿色徽章 + **整行红色 plain 大按钮「🗑️ 清除已设授权码」** 替换输入框 |
| **未设置** | 显示 `type="password"` 输入框 + "未设置"灰色徽章 |
| **清除流程** | confirm → 调 PUT `password=""` → `isPasswordSet` 变 false → UI 自动切回输入框，可立即输入新值 |

为什么这么做？API 约定 `password=null/undefined` 不动 / `""` 清空 / 其它=明文。如果保留输入框，用户没动密码字段时若直接 PUT 会误清空。隐藏输入框（已设状态）+ 独立清除按钮，意图清晰、不会误操作。

`passwordTouched` 标志保护：仅当用户输入过密码（非清空操作）才把 `password` 字段加进 PUT payload。

#### "什么是授权码" popover 内容

```
授权码是邮箱服务商发放的、专门给第三方客户端使用的"代密码"。

• QQ / 163 / 126 / 新浪 等：必须使用授权码，邮箱后台「设置 → 账户」开 SMTP/IMAP 后获取
• Gmail / Outlook 等：开启「应用专用密码」后使用
• 企业邮 / 自建 SMTP：通常直接使用登录密码即可

💡 在邮箱网页端搜索「授权码」或「SMTP」可快速找到入口
```

#### 测试发邮件按钮的 dirty 联动

按钮调的是后端**已保存**的配置，不是对话框临时编辑值。如果 dirty=true（用户改过未保存）按钮 disable + tooltip "请先保存当前修改后再测试"，避免"改了 SMTP 没保存就点测试 → 用旧配置发 → 用户以为新配置通过了"的陷阱。

### 8. 登录 418 紧急修

#### 现象

登录页输入未注册账号，后端返回 `{code:418, msg:"用户名密码不存在，请注册"}`，但前端：
- 桌面端：弹出 "登录已过期，请重新登录"（误导，用户根本没登录过）
- 移动端：跳到 mode=0（没毛病）但弹同样 alert
- **桌面端实际还根本没跳到注册 mode**，因为拦截器跳转 logic 里有 `currentPath.startsWith('/auth') return` early return

#### 根因

`request.ts` 拦截器对 401/418/4010/4011 一刀切当成"认证失效"，调 `globalHandlers.onUnauthorized?.()` + 把 ApiError msg 替换成 "登录已过期"。

但**登录/注册接口里收到 418 是业务语义**（"用户不存在 / 密码错"），不是"token 失效"，不该走全局跳转。

#### 修复

```ts
// request.ts
const url = response.config.url || ''
const isAuthEndpoint = url.includes('/auth/login') || url.includes('/auth/register')

if (AUTH_ERROR_CODES.includes(code) && !isAuthEndpoint) {
  // 全局跳转 + 替换 msg
}

// 登录/注册接口的认证错误码：保留原始 msg，handled=false 让业务自己处理
if (isAuthEndpoint && AUTH_ERROR_CODES.includes(code)) {
  return Promise.reject(new ApiError(code, msg, false, false))
}
```

`Auth.vue` 的 catch：

```ts
if (err?.code === ApiCode.NOT_REGISTERED && isLogin.value) {
  ElMessage.warning(err.message)  // 显示后端真实 msg
  router.replace({ path: '/auth', query: { ...route.query, mode: '0' } })
  password.value = ''  // 清空密码（保留用户名引导继续）
  return
}
```

### 11. 路由污染 bug 全面修复

#### 现象（用户报的旧 bug）

1. `/setting/type`（分类列表）
2. 点 + 进 `/setting/type/add`
3. 填写后保存 → `router.push('/setting/type')`
4. 在新落地的列表点 ← 返回
5. 期望：回 `/setting`
6. **实际：又回到 `/setting/type/add`** ❌

#### 根因

`routeHistory.ts` 自维护 history 不区分 push/replace，afterEach 无脑 push 所有路径。所以 `add → 列表` 的"提交完成跳转"会留下 add 路径：

```
history: [/setting, /setting/type, /setting/type/add, /setting/type]
                                                       ↑ 当前
```

列表 onBack → smartBack → getPrevious：
- pop 当前（最后一个 /setting/type）
- 取末尾 = /setting/type/add ← 错误目标

#### 修复

routeHistory 自己其实留了 `removeWhere(predicate)` 工具方法（注释里写明就是给这种场景的），但只有 ScheduledFlowAdd.vue 用了。其他 4 个 *Add 都没用。

抽糖到 `useSmartBack` 共享：

```ts
function replaceAfterSubmit(listPath: string, prefixes?: string[]) {
  const list = prefixes ?? [`${listPath}/add`, `${listPath}/edit`]
  routeHistory.removeWhere((p) => list.some((prefix) => p.startsWith(prefix)))
  router.replace(listPath)
}
```

调用方：
```ts
const { replaceAfterSubmit } = useSmartBack()
// 提交完成
replaceAfterSubmit('/setting/type')  // 自动清 /setting/type/add* 和 /setting/type/edit*
```

5 个文件 / 9 处替换：
- `TypeAdd.vue` 3 处（保存 / 归档 / 停用）
- `AccountAdd.vue` 1 处
- `ActionAdd.vue` 1 处
- `TemplateAdd.vue` 2 处（保存 / 删除）
- `ScheduledFlowAdd.vue` 2 处（删本地 `pruneAddEditHistory` + `useRouteHistoryStore` import，统一用共享 API）

修复后链路：
```
1. /setting/type → /setting/type/add（push）
   history: [..., /setting/type, /setting/type/add]

2. 保存 → replaceAfterSubmit('/setting/type')
   - 第一步：removeWhere 清掉 /setting/type/add* /setting/type/edit*
     history: [..., /setting/type]
   - 第二步：router.replace('/setting/type')
     afterEach push 时排重逻辑生效（末尾已是 /setting/type，不重复）

3. 在列表点 ← → smartBack('/setting')
   getPrevious(): pop 当前 → [...]
   返回末尾 = /setting ✓
```

## 遇到的坑 / 注意事项

### 1. element-plus dark 主题给 input__inner 加独立背景

第一版以为 `var(--color-bg-card)` 在 dark 下会自动适配，结果用户截图显示"中间大黑色块超出整个元素的高度"。要显式 `background: transparent !important` 覆盖 element-plus dark 的 `var(--el-fill-blank)`。InputNumber 的 inner 还要用更具体选择器（`.el-input-number .el-input__inner`）覆盖。

### 2. element-plus 给 input-number 上下箭头按钮独立浅灰底

之前我只改了 inner，箭头按钮还是默认浅灰底，dark 下偏深。要单独覆盖 `.el-input-number__increase / __decrease` 的 background 为 transparent，hover 用主题色半透明（dark 用 `#74c0fc` 偏亮蓝）。

### 3. el-segmented 在 dark 下"白胶囊撞黑底"

我第一版 dark 下选中胶囊用了 `rgba(255,255,255,0.95)`（几乎纯白），用户说太刺眼。改成 `rgba(255,255,255,0.1)` 玻璃感半透明 + 偏亮蓝边 `rgba(116,192,252,0.6)` + 字 `#74C0FC`。这跟 time-picker 时钟 icon 同色，全屋统一。

### 4. el-popover popper 在 dark 下不会自动适配

el-popover 默认主题没跟 dark mode 联动（不像 dialog/drawer 等内置组件）。要显式：
```css
html.dark .sf-info-popover.el-popover {
  background: rgba(40,40,42,0.98) !important;
  border-color: rgba(255,255,255,0.08) !important;
}
html.dark ... .el-popper__arrow::before { ... }  /* 三角也要适配 */
```

### 5. routeHistory 自维护 + 不区分 push/replace 是项目级坑

每个 `*Add` 页面提交跳列表都得记得 `replaceAfterSubmit`（或者手写 `removeWhere`）。新加任何 add/edit 页面时这是必备样板。建议下次新增同类页时把这步加进 PR 模板的 review checklist。

### 6. vant 的 segmented 不存在，自己实现

vant 4 没有 segmented 组件。用 `van-radio-group` 视觉差距大，`van-tabs sticky type=card` 也不像 segmented。最终自己写 `.sys-mob-segmented` div + flex item，配合 `.is-block` 让它能在 cell title 内占整行。这个共享类还会被未来的其他移动端页面用到（任何"小集合多选一"场景）。

### 7. 移动端 cell-group inset 之间默认无间距

vant `<van-cell-group inset>` 默认上下 margin 0，多个 cell-group 连起来"坨在一起"。共享 css 加：
```css
.sys-mob-body .van-cell-group--inset { margin-bottom: 12px; }
```

桌面端的 `el-card` / 自定义 `.info-section` 不存在这个问题（项目本来 gap 控制）。

### 8. emoji 渲染差异：☀ vs ☀️

带 variation selector（U+FE0F）的 `☀️` 在大部分浏览器渲染成彩色 emoji 表情；不带的 `☀` 是黑白文字字符。第一版我用了不带 selector 的 `☾ ☀ ⚙`，用户说"黑漆漆"。要么用 `☀️🌙⚙️`，要么用真正的 SVG icon。

### 9. 子组件不要直接绑 `:model-value="props.data.xxx"`

会被父级 props 更新覆盖用户编辑中的值。子组件本地 `ref` + `watch(props.data, ...)` 单向同步 + 控件 v-model 绑本地 ref 才安全。debounce 期间外部 props 不变（没人 reload），不会覆盖本地输入。

### 10. SystemInfo / 系统信息 → SystemSettings / 系统设置 命名变更

不止改文件名 / 卡片入口，还顺带把"系统信息"这种偏向纯展示的语义改成"系统设置"（暗示可编辑）。这是产品层面的对齐，桌面 + 移动两端文案都改了。

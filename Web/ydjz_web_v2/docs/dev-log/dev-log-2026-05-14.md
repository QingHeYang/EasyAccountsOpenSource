## 今日开发内容

### 1. 产品决策：统计主页日级，分类详情月级

#### 用户原话
> "我点进内部去，他是按月拆分的样式啊，这个涉及到产品的思路了啊"
> "其实统计的意义就是统计分类（科目）在一定时间的影响……是从统计把日子完整的继承进来，然后展示，还是分类只看月份"
> "好的，按你说的来，先改桌面端，增加日期的选择，跳转过去，传过去完整时间，但是，只使用到月份，也就是说，分类不用改"

#### 解读
两个页面的产品语义本来就不同：
- **统计主页**：横切——「在 X 时间段里，所有分类各自影响多少」。时间窗口的精度决定了"对账"的颗粒度，用户想"看上周/这 3 天花了多少"是合理诉求。
- **分类详情**：纵切——「这一个分类，在过去一段时间里月度趋势是什么样的」。最小粒度就是月，再细没意义（一个分类一天的金额没有"月度趋势"的内涵）。

所以两边时间表示形式可以不同，跳转时主页 → 详情传 `yyyy-MM-dd`，详情自己 `substring(0, 7)` 退到月份就行，不影响详情页内部按月的渲染逻辑。

### 2. PC 端改动

#### `AnalysisMain.vue`

新增 / 替换的工具函数：

```ts
function formatYMD(date: Date): string {
  const y = date.getFullYear()
  const m = String(date.getMonth() + 1).padStart(2, '0')
  const d = String(date.getDate()).padStart(2, '0')
  return `${y}-${m}-${d}`
}

function firstDayOf(year: number, month: number): Date {
  return new Date(year, month, 1)
}

function lastDayOf(year: number, month: number): Date {
  return new Date(year, month + 1, 0)
}
```

`calcDateRange` 7 个 case 全部覆盖完整自然月起止 + 当月只到今天：

```ts
case 0: // 当月：1 号 ~ 今天
  return { start: formatYMD(firstDayOf(year, month)), end: today }
case 1: // 上月：上月 1 号 ~ 上月最后一天
  return {
    start: formatYMD(firstDayOf(year, month - 1)),
    end: formatYMD(lastDayOf(year, month - 1)),
  }
// 近 3/6 月、近 1 年、本年、上年 同理
```

### 3. 移动端改动

#### `Analysis.vue`

工具函数同 PC：

function formatYMD(date: Date): string {

  const m = String(date.getMonth() + 1).padStart(2, '0')
  const d = String(date.getDate()).padStart(2, '0')

`onFastChoose` 7 case 输出 `yyyy-MM-dd`。

**picker 数组兼容老数据**：早期默认值或缓存可能还是 `yyyy-MM`，加一个 `initPickerArr` helper：

```ts
function initPickerArr(date: string): string[] {
  const parts = date.split('-')
  // 兼容老数据 yyyy-MM → 自动补 '01'
  if (parts.length === 2) return [...parts, '01']
  return parts.slice(0, 3)
}
```

`onStartConfirm` / `onEndConfirm` 用 `${y}-${m.padStart(2,'0')}-${d.padStart(2,'0')}` 拼回 `yyyy-MM-dd`，并做"开始 ≤ 结束"校验。

function initDateRange() {

## 遇到的坑 / 注意事项

### 1. picker 数组旧值兼容

移动端 `van-date-picker` 用 `string[]` 做 v-model。`columns-type` 从 2 段变 3 段时，如果某处兜底数据还是 `[y, m]` 直接塞进去，picker 渲染会少一列、用户体验诡异。所以：

- 主页 picker 初始化用 `initPickerArr`，老的 `yyyy-MM` 自动补 `'01'` 当日；
- 详情页因为内部仍是 2 段，直接 `.slice(0, 2)` 兜底，防上游传来 3 段日期。

### 2. 接口兼容前提

后端这次扩展是「字符串解析端宽松化」——`yyyy-MM` 和 `yyyy-MM-dd` 都接受，且可以混传（start 月、end 日）。所以前端老链路（详情页传月）不需要任何改动也照常工作，**这次改动是纯追加**，不会动到任何兼容性。

### 3. 详情页不动 = 用户验收最小代价

把"统计的精度"全部放在主页解决，详情页一行 substring 兜住跳转入口，不动 UI、不动月份滚动、不动按年分组渲染——验收只需要点开几个分类看看月份还正确就行。

### 4. 跳转入口的传参契约

主页 emit `typeClick(typeId, startDate, endDate)` 时 `startDate` / `endDate` 已经是 `yyyy-MM-dd`，PC 是 prop 透传到 `TypeDetail.initialStartDate/EndDate`，移动是 query 字符串。两侧详情页负责截月——**约定写在详情页这一端**，主页不区分。

### 2. 剪贴板兼容性修复

#### 2.1 问题描述

生产环境使用 HTTP 协议，`navigator.clipboard.writeText()` 只在安全上下文（HTTPS/localhost）可用，导致复制功能失败。

#### 2.2 解决方案

创建 `src/shared/utils/clipboard.ts` 提供降级方案：

```typescript
export async function copyToClipboard(text: string): Promise<boolean> {
  // 优先使用现代 API（HTTPS 环境）
  if (navigator.clipboard && window.isSecureContext) {
    try {
      await navigator.clipboard.writeText(text)
      return true
    } catch { }
  }

  // 降级方案：使用 execCommand（HTTP 环境）
  try {
    const textArea = document.createElement('textarea')
    textArea.value = text
    textArea.style.cssText = 'position:fixed;top:-9999px;left:-9999px'
    document.body.appendChild(textArea)
    textArea.focus()
    textArea.select()
    const success = document.execCommand('copy')
    document.body.removeChild(textArea)
    return success
  } catch {
    return false
  }
}
```

#### 4.3 【重大 Bug】模板无分类时绕过验证

**问题描述**：

使用没有选择分类的模板时，可以成功提交流水，但流水没有分类。

**根本原因**：

后端 API 对于未选择分类的模板，返回的不是 `null`，而是空对象：

```json
{
  "type": { "id": 0, "tname": null }
}
```

原来的验证逻辑只检查对象是否存在：

```typescript
// 错误的检查方式
if (!selectedType.value) {  // { id: 0, tname: null } 是 truthy
  showToast('请选择分类')
  return false
}
```

**修复方案**：

检查具体字段而非对象本身：

```typescript
// 模板应用时
if (template.type?.tname) {
  selectedType.value = { id: template.type.id, tname: template.type.tname }
}

// 账户检查
if (template.account?.name) {
  selectedAccount.value = accounts.value.find(a => a.id === template.account!.id) || null
}

// 收支检查
if (template.action?.hname) {
  selectedAction.value = actions.value.find(a => a.id === template.action!.id) || null
}

// 验证时
if (!selectedType.value?.tname) {
  showToast('请选择分类')
  return false
}
```

**对比旧项目**：

旧项目（ydjz_web）使用 JavaScript 松散相等：
```javascript
if (this.template.typeId == null)  // 0 == null 为 false，但不会匹配到 0
```
但旧项目用的是 `typeId == ""` 判断，而 `0 == ""` 在 JS 中为 true，所以能正确拦截。

新项目使用 TypeScript 严格模式，需要显式检查字段值。

## 技术要点

### 1. 安全上下文与剪贴板 API

`navigator.clipboard` 只在以下环境可用：
- HTTPS 协议
- localhost
- file:// 协议

HTTP 环境需要使用 `document.execCommand('copy')` 降级。

### 2. API 返回空对象 vs null

后端返回未填充的关联对象时，可能返回：
- `null`（理想情况）
- `{ id: 0, field: null }`（空对象）

前端应检查具体业务字段（如 `?.tname`），而非仅检查对象是否存在。

### 3. Pinia Store 用于表单状态暂存

跨页面保存表单状态的常见模式：
1. 离开页面前保存到 Store
2. 返回页面时从 Store 恢复
3. 成功提交后清空 Store

### 6. 总览页面资产显示优化

#### 6.1 exemptAsset 判断修复

**需求**：当账户的 `exemptAsset` 为 0 或 0.00 时，不显示净资产（realAsset）。

**原逻辑**：
```typescript
realAsset: acc.exemptAsset
  ? (parseFloat(acc.accountAsset) - parseFloat(acc.exemptAsset)).toFixed(2)
  : null
```
问题：`"0.00"` 是 truthy，会显示 realAsset。

**新逻辑**：
```typescript
const exempt = parseFloat(acc.exemptAsset || '0')
const hasExempt = exempt !== 0
realAsset: hasExempt
  ? (parseFloat(acc.accountAsset) - exempt).toFixed(2)
  : null
```

#### 6.2 净资产显示

**需求**：在总资产卡片中显示净资产，但仅当 `netAsset !== totalAsset` 时显示。

**实现**：
```typescript
// 计算属性
const showNetAsset = computed(() => {
  if (!homeInfo.value) return false
  return homeInfo.value.netAsset !== homeInfo.value.totalAsset
})
```

```vue
<!-- 模板 -->
<div class="asset-net" v-if="showNetAsset">
  净资产 ¥ {{ homeInfo?.netAsset || '0.00' }}
</div>
```
